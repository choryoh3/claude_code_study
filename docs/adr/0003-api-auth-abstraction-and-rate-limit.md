# 0003. 認証の抽象化とメモリ方式のレート制限

- 日付: 2026-10-19
- 状態: 採用（レート制限は本番前に見直す）

## 背景

公開APIなので、認証とレート制限が必要。Supabase Auth は GitHub OAuth を未設定で、本番のストアも未接続。

## 決定

- 認証は `AuthProvider` 抽象の裏に置く。未接続の間は `guestAuthProvider`（常にゲスト）を既定とし、Supabase JWT 検証は同じインターフェースの実装として後から差し替える
- 進捗・バッジのAPIはログイン必須（401）。ゲストの進捗はクライアントのlocalStorageに持ち、ログイン時に `POST /api/progress/merge` で取り込む。マージは進捗を後退させない
- クイズは、ゲストでも採点できる。採点は必ずサーバー側で行い、正解と解説は採点結果でのみ返す
- レート制限は固定ウィンドウのメモリ実装。全リクエストに上限、書き込み系にはさらに厳しい上限をかける

## 結果

- メモリ方式はサーバーレスの複数インスタンス間で共有されないため、上限が実質的に緩くなる。本番公開前に Upstash 等の共有ストアへ差し替える必要がある
- クライアントIPは `x-forwarded-for` を信頼している。Vercel では付与されるが、他のホスティングでは見直す
