# 0005. Web UI の土台（デザイントークン・ゲスト進捗・サーバー/クライアント境界）

- 日付: 2026-10-19
- 状態: 採用

## 背景

フェーズ4で、デザインシステム・レッスン画面・ダッシュボード・ロードマップを作る。
Supabase Auth は未接続で、API の Next.js へのマウントはフェーズ5で行う。

## 決定

- **スタイル**: Tailwind は使わず、CSS 変数(デザイントークン)＋CSS Modules。色・余白・角丸・影・動きは `globals.css` のトークンだけから使う。ライト/ダークは `data-theme`（未指定なら OS 設定）で切り替える。色は WCAG AA を満たす組み合わせに限る
- **フォント**: `next/font` でWebフォントを取得せず、日本語対応のシステムフォントスタックを使う（ビルドが外部ネットワークに依存せず、表示も速い）
- **レッスンの描画**: レッスン(MDX)はサーバーで `next-mdx-remote/rsc` により描画し、`generateStaticParams` で静的生成する。`dynamicParams = false`。未公開の中級・上級トピックは「準備中」ページを返し、「次へ」のリンクが切れないようにする
- **ゲストの進捗**: ログイン前の進捗は localStorage に保存する（`GuestProgress`）。形は API の `POST /api/progress/merge` の入力に合わせ、ログイン時にそのまま取り込める。連続学習日数の計算は API と共有するため `packages/schemas` に置く
- **サーバー/クライアント境界**: `node:fs` を使う `lib/lessons.ts` はサーバー専用。ブラウザ側のコンポーネントが使う `lessonHref` は別ファイル(`lib/lesson-href.ts`)に分ける（混ぜるとクライアントのバンドルに `node:fs` が入り、ビルドが失敗する）
- **ハイドレーション**: localStorage に依存する表示は、`useIsClient` で準備ができるまで隠す／骨組みにする（全員に「未着手」が一瞬見えるのを避ける）

## 結果

- 進捗はブラウザごとに保存される。端末をまたぐ同期は、ログイン（Supabase Auth）後のフェーズで行う
- API のマウントはフェーズ5。それまで画面はコンテンツと localStorage だけで動く
