# 0006. フェーズ5 学習機能（API のマウント・ゲストのバッジ・検索・リファレンス）

- 日付: 2026-10-19
- 状態: 採用

## 背景

フェーズ5で、クイズ・進捗・バッジ・検索・チートシートを作る。Supabase Auth の GitHub ログインは未設定（有効なのは email のみ）で、本番用の永続ストアも未接続。

## 決定

- **APIのマウント**: Hono を Next.js の Route Handler（`app/api/[[...route]]`）にマウントし、1つのVercelプロジェクトで運用する（ADR 0002）。`@claude-study/api/app` は Prisma を含まない入口として分け、Next のビルドにネイティブモジュール（better-sqlite3）が入らないようにする
- **ストアは「未接続」で固定**: ログインが無い間、進捗・バッジの API は401を返し、クイズ採点もゲストは保存しないので、ストアは呼ばれない。誤って呼ばれたら、原因が分かる例外にする。Supabase 接続後に `createPrismaStore` へ差し替える
- **採点はサーバーで行う**: 正解と解説は、採点結果でのみ返す。クイズの取得 API には含めない
- **選択肢はクライアントで毎回シャッフル**: 正解位置の偏り（0番:13問 / 1番:20問 / 2番:4問）から答えを推測できないようにする。採点には元の番号を送る
- **ゲストのバッジ**: バッジの定義と判定ロジックを `packages/schemas` に置き、API とブラウザで同じ判定を使う。ブラウザでは `BadgeEngine` が学習状態を見張り、条件を満たしたら付与してトーストで知らせる（付与済みは再判定しないので、二重に祝わない）
- **型付きAPIクライアント**: ブラウザからは Hono RPC（`hc<AppType>`）で呼ぶ。ルートの入出力の型が、API の定義から自動で決まる
- **検索**: ⌘K / Ctrl+K のコマンドパレット。ページ・レッスン（APIの全文検索）・チートシート/用語集を横断する。ネイティブの `<dialog>` を使い、フォーカスの閉じ込めと Esc での閉じる動作はブラウザに任せる
- **チートシート・用語集は、データ（YAML）とコードを分ける**: `packages/content/reference/*.yaml`。ロード時に zod で検証し、解説先レッスン(`lesson`)が実在しなければビルドを失敗させる。内容は既存の検証済みレッスンだけを情報源にする
- **アイコン**: 絵文字や記号文字ではなく、`lucide-react` を使う（必要なアイコンだけがバンドルされる）
- **ナビゲーション**: 広い画面はヘッダー、狭い画面は親指で届く下部タブバー

## 結果

- ゲストのクイズ満点は、ログイン時の merge API では引き継がれない（merge の入力にクイズ結果がないため）。サーバー側のバッジは、サーバーに記録された受験結果から判定する。必要になったら merge の入力にクイズ結果を足す
- 進捗・バッジの端末間同期は、GitHub ログインの有効化（Supabase 側の設定）と、ストア接続のあとで行う
- 公開APIのレート制限はメモリ実装（ADR 0003）。本番では共有ストアへの差し替えが必要
