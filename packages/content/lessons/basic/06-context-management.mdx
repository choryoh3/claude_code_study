## ゴール

- コンテキストウィンドウとは何かを説明できる
- `/context`、`/compact`、`/clear`、`/rewind` を場面に応じて使い分けられる
- 自動コンパクトで何が起きるかを知り、慌てずに対処できる

## 前提

- Claude Codeで数回やり取りした経験があること(レッスン2、3)

用語の説明です。**コンテキストウィンドウ** は、Claudeが一度に覚えておける情報の容量です。あなたの指示、Claudeが読んだファイル、Claudeの返答などがすべて入ります。**トークン** は、その量を数える単位です。

## 解説

### なぜ管理が必要か

Claude Codeは、リクエストのたびに会話全体を送ります。会話が長いほど、1回ごとの消費が増え、公式も、無関係な古い内容は後続のメッセージのトークンを無駄にすると説明しています。

### 主なコマンド

| コマンド          | 役割                                                                                          |
| :---------------- | :-------------------------------------------------------------------------------------------- |
| `/context`        | 使用状況を色付きのグリッドで表示。重いツールやメモリ肥大の提案も出る                          |
| `/compact [指示]` | 会話を要約して容量を空け、同じ会話を続ける。指示で残す内容を指定できる                        |
| `/clear [名前]`   | 空のコンテキストで新しい会話を始める。名前を付けると前の会話を `/resume` の一覧で見分けやすい |
| `/resume`         | 過去の会話を再開する(名前やIDでも指定できる)                                                  |
| `/rewind`         | 会話やコードを以前の時点まで戻す。または選んだメッセージから要約する                          |
| `/btw 質問`       | 会話に追加せず、横道の質問をする                                                              |

`/rewind` では、メッセージを選んで **Summarize from here** や **Summarize up to here** を選ぶと、会話の一部だけを要約できます。作業中に方向を誤ったら、`Esc` で止められます。`Esc` を2回押すと戻る操作(`/rewind`)も使えます。

### 使い分けの目安

- 別の作業に移る: `/clear`
- 同じ作業を続けたいが会話が長い: `/compact`(例: `/compact focus on the auth bug fix`)
- 今どれくらい使っているか不明: `/context`

### 自動コンパクト

上限に近づくと、Claude Codeは自動で会話を要約します。満杯でもセッションは終わりません。コンパクト後も、プロジェクトルートの `CLAUDE.md` はディスクから再読み込みされ、Plan Modeで作った計画も保持されます。一方、会話の中だけで伝えた細かい指示は、要約で落ちることがあります。守ってほしいルールは `CLAUDE.md` に書いておくのが確実です(次の次のレッスン)。

## ハンズオン

1. 練習用フォルダでClaude Codeを起動し、何か簡単な質問を2〜3回します。
2. 使用状況を確認します。

   ```text
   /context
   ```

   期待される結果: コンテキストの使用状況がグリッドで表示されます。

3. 要約の焦点を指定して圧縮します。

   ```text
   /compact 直前の質問の結論だけを残して
   ```

   期待される結果: `Conversation compacted` のようなメッセージが出て、会話が要約に置き換わります。もう一度 `/context` で使用量が減ったことを確認します。

4. 会話に名前を付けてから、新しく始めます。

   ```text
   /clear compact-practice
   ```

   期待される結果: 空の会話になります。

5. 前の会話に戻ります。

   ```text
   /resume
   ```

   期待される結果: 一覧が表示されます。`compact-practice` を選ぶと、前の会話が再開されます。

## よくある失敗

- **何時間も同じ会話を使い続ける**
  - 原因: 無関係な作業でも履歴が積み上がる
  - 対処: 作業の区切りで `/clear` する。戻る可能性があるなら名前を付けて `/resume` で戻れるようにする
- **`/clear` で消えたと思って慌てる**
  - 原因: 前の会話が消えると誤解している
  - 対処: `/resume` で再開できる。ただし、新しい会話に前の内容は引き継がれない
- **コンパクト後にClaudeが指示を忘れる**
  - 原因: 会話中だけで伝えた指示が要約で落ちた
  - 対処: 長期のルールは `CLAUDE.md` に書く。コンパクト前に `/compact` に残したい内容を指示する
- **要約をむやみに繰り返す**
  - 原因: 容量が気になって何度も実行する
  - 対処: `/compact` は会話を読んで要約するため、それ自体にコストがかかる。無関係な作業に移るなら `/clear` のほうが軽い
- **見当違いの方向に進んだのに、そのまま続ける**
  - 原因: 止めるタイミングを逃している
  - 対処: `Esc` で止め、`/rewind` で戻る。間違いを積み上げた会話を要約するより、戻るほうがきれい
