## ゴール

- 権限モードとは何かを説明できる
- 主要なモードの違いと、`Shift+Tab` での切り替え方を理解する
- 「便利さ」と「安全さ」のどちらを取るかを、作業内容に応じて選べるようになる

## 前提

- Claude Codeをインストールし、`claude` で起動できること(レッスン1〜3)
- 練習用の、壊れても困らないフォルダを用意すること

用語の説明です。**権限(パーミッション)** とは、Claudeがファイル編集やコマンド実行などの操作を「確認なしで実行してよいか」の取り決めです。**権限モード** は、その基本方針をまとめて切り替えるスイッチです。

## 解説

### 主なモード

公式ドキュメントで確認した、設定値と概要です。

| 設定値                     | 確認なしで実行されるもの                                         | 向く場面                               |
| :------------------------- | :--------------------------------------------------------------- | :------------------------------------- |
| `default`(画面上は Manual) | 読み取りのみ                                                     | 一つ一つ確認したい、慎重に進めたい作業 |
| `acceptEdits`              | 読み取り、ファイル編集、`mkdir` `touch` `mv` `cp` などの基本操作 | 変更を後から `git diff` で確認する作業 |
| `plan`                     | 読み取りのみ(編集は計画の承認まで不可)                           | 実装前の調査(次のレッスン)             |
| `auto`                     | ほぼ全て(裏で別のモデルが安全性をチェック)                       | 長い作業で確認の手間を減らしたい       |
| `dontAsk`                  | 事前に許可したものだけ。確認が必要なものは拒否                   | CIなど人がいない環境                   |
| `bypassPermissions`        | 全て(チェックなし)                                               | 隔離されたコンテナやVMだけ             |

注意点が2つあります。

- バージョンや契約プランによっては、起動時のモードが最初から `auto` になっています。まずステータスバーで今のモードを確認してください。
- 「拒否ルール(deny)」は `bypassPermissions` を含む全モードで効きます。モードは基本方針で、個別のルール設定はその上に重ねます(ルールの書き方は中級で扱います)。

### モードの切り替え方

| 方法   | 内容                                                                                                             |
| :----- | :--------------------------------------------------------------------------------------------------------------- |
| 実行中 | `Shift+Tab` で循環する。`default` → `acceptEdits` → `plan` の順で、`auto` などは利用可能な場合にその後ろに加わる |
| 起動時 | `claude --permission-mode plan` のようにフラグで指定する                                                         |
| 既定値 | 設定ファイルの `permissions.defaultMode` に書く                                                                  |

現在のモードはプロンプト下のステータスバーに表示されます(例: `⏸ manual mode on`、`⏵⏵ accept edits on`、`⏸ plan mode on`)。`dontAsk` は `Shift+Tab` の循環には出ず、`--permission-mode dontAsk` で指定します。`bypassPermissions` も、有効化して起動した場合にだけ循環に加わります。

### `/permissions` コマンド

セッション中に `/permissions` と入力すると、許可・確認・拒否のルールを一覧し、追加・削除できる画面が開きます。詳しい設定は中級で扱います。

## ハンズオン

1. 練習用フォルダでClaude Codeを起動します。

   ```bash
   mkdir perm-practice
   cd perm-practice
   claude
   ```

2. プロンプト下のステータスバーを見て、今のモード名を確認します。
3. `Shift+Tab` を1回ずつ押し、表示が変わる様子を観察します。`manual mode on`、`accept edits on`、`plan mode on` などが順に出ます。
4. `manual mode on` に合わせ、次のように依頼します。

   ```text
   hello.txt を作って、中に「こんにちは」と書いて
   ```

   期待される結果: ファイル作成の許可を求める確認が表示されます。内容を読んで承認してください。

5. `Shift+Tab` で `accept edits on` に切り替え、次を依頼します。

   ```text
   hello.txt に2行目「2行目です」を追加して
   ```

   期待される結果: 確認なしで編集されます。

6. `/permissions` を実行し、ルールの画面を眺めて閉じます。

## よくある失敗

- **起動直後のモードを確認せずに作業を始める**
  - 原因: 起動時のモードが環境ごとに違う(`auto` から始まることもある)
  - 対処: 最初にステータスバーを見る習慣をつける。慎重にいきたいときは `claude --permission-mode default` で起動する
- **確認が面倒で `bypassPermissions` を普段使いする**
  - 原因: `--dangerously-skip-permissions` が手軽に見える
  - 対処: このモードは安全チェックを外し、悪意ある指示への対策も効きません。隔離されたコンテナやVMだけで使う。普段は `acceptEdits` や `auto` で足りる
- **`acceptEdits` で「何でも勝手にされる」と誤解する**
  - 原因: 自動承認の範囲を知らない
  - 対処: 自動承認は作業ディレクトリ内の編集と基本的なファイル操作のみ。それ以外のコマンドは確認される。`.git` や `.claude` などの保護対象への書き込みも確認される
- **`Shift+Tab` を押しても目的のモードに行かない**
  - 原因: `dontAsk` は循環に含まれない。`bypassPermissions` は有効化して起動しないと現れない
  - 対処: `--permission-mode` フラグで起動し直す
- **許可ルールを広く書きすぎる**
  - 原因: 確認の手間を減らそうとして、コマンド全般を許可してしまう
  - 対処: 許可は対象を絞り、取り消せない操作(削除や強制pushなど)は確認が出る状態を保つ
