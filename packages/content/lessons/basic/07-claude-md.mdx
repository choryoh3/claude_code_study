## ゴール

- CLAUDE.md が何のためのファイルか説明できる
- 置き場所ごとの違い（個人・プロジェクト・ローカル）を使い分けられる
- `/init` で下書きを作り、`/memory` と `/context` で読み込みを確認できる

## 前提

- Claude Code をインストール済みで、プロジェクトのフォルダで起動できる
- 前のレッスンの `/clear` や `/compact` など、コンテキスト（Claude が一度に覚えておける会話や読み込み内容の範囲）の考え方を知っている

## 解説

### CLAUDE.md とは

Claude Code は、セッションを開始するたびに白紙の状態から始まります。そこで「このプロジェクトのテストはこう実行する」「命名規則はこう」といった、毎回説明したくなる内容を書き残しておくのが CLAUDE.md です。通常の Markdown ファイルで、セッション開始時に読み込まれます。

大事な注意点があります。公式は CLAUDE.md を「強制される設定」ではなく「コンテキスト（参考情報）」だと説明しています。絶対に守らせたいことは、中級で扱う hooks や権限設定で担保します。

### 置き場所と読み込み順

| 種類               | 場所                                                                       | 用途                                            |
| ------------------ | -------------------------------------------------------------------------- | ----------------------------------------------- |
| 組織の管理ポリシー | Windows は `C:\Program Files\ClaudeCode\CLAUDE.md`（macOS・Linuxは別パス） | 組織全体の指示。IT部門が管理                    |
| ユーザー           | `~/.claude/CLAUDE.md`                                                      | 全プロジェクト共通の個人設定                    |
| プロジェクト       | `./CLAUDE.md` または `./.claude/CLAUDE.md`                                 | チームで共有（Git管理）                         |
| ローカル           | `./CLAUDE.local.md`                                                        | 個人かつプロジェクト固有。.gitignore に追加する |

公式の表は、この順（広い範囲から具体的な範囲へ）が読み込み順です。ファイルは上書きではなく、すべて連結されてコンテキストに入ります。作業ディレクトリとその上位ディレクトリにある CLAUDE.md は起動時に読み込まれ、サブディレクトリにあるものは、Claude がそのディレクトリのファイルを読んだり編集したりした時点で読み込まれます。

### 何を書くか

良い例は、確認できるほど具体的で短い指示です。

- 良い: 「コミット前に `pnpm test` を実行する」「API ハンドラは `src/api/handlers/` に置く」
- 悪い: 「テストをちゃんとする」「ファイルを整理して置く」

公式の目安は次のとおりです。

- 1 ファイル 200 行未満にする。長いと読み込みコストが増え、指示が守られにくくなる
- 書く: Claude が推測できないコマンド、デフォルトと違う規約、環境の癖
- 書かない: コードを読めば分かること、自明な心得、頻繁に変わる情報
- 矛盾する指示は避ける（Claude がどちらかを任意に選ぶことがある）

なお `@path/to/file` と書くと別ファイルを取り込めますが、取り込んだファイルも起動時に読み込まれるため、コンテキストの節約にはなりません。

### メモリの仕組み（auto memory）

CLAUDE.md とは別に、Claude 自身があなたの訂正や好みをメモする「auto memory」があります。こちらは Claude が書き、CLAUDE.md はあなたが書きます。保存先は `~/.claude/projects/<project>/memory/` で、`/memory` から中身を見たり編集したりできます。「CLAUDE.md に追加して」と頼めば、CLAUDE.md の方に書いてもらえます。

## ハンズオン

1. 練習用のフォルダ（または自分のプロジェクト）で Claude Code を起動します。

   ```bash
   claude
   ```

2. `/init` を実行します。

   ```text
   /init
   ```

   期待される結果：Claude がコードベースを調べ、ビルドコマンドやテスト手順などを含む `CLAUDE.md` を作ります。すでにある場合は、上書きせず改善案を出します。

3. 生成された `CLAUDE.md` を開き、不要な行を削ります。各行について「消すと Claude が間違えるか？」と自問し、そうでなければ削除します。

4. 次の 2 行を追加します（コマンドは自分のプロジェクトに合わせてください）。

   ```markdown
   - コミット前に `pnpm test` を実行する
   - 回答は日本語で書く
   ```

5. いったん `/exit` で終了して `claude` を起動し直し（新しいセッションにする）、読み込みを確認します。

   ```text
   /context
   ```

   期待される結果：一覧の **Memory files** に、プロジェクトの `CLAUDE.md` が表示されます。

6. `/memory` を実行します。

   期待される結果：ユーザー用・プロジェクト用の CLAUDE.md の場所と、auto memory のオン/オフ切り替え、auto memory フォルダを開く選択肢が表示されます。

7. 「このプロジェクトでは何語で回答する決まり？」と質問し、追記した方針が反映されるか確かめます。

## よくある失敗

- **CLAUDE.md を作ったのに無視される**
  原因：ファイルが読み込まれていない、指示が曖昧、または指示同士が矛盾している。対処：`/context` の Memory files で読み込みを確認し、指示を具体的に書き直し、矛盾を消す。
- **サブディレクトリの CLAUDE.md が効かない**
  原因：サブディレクトリのものは起動時ではなく、そのディレクトリのファイルを Claude が読んだ時に読み込まれる。対処：Memory files に出なくても異常ではない。そのディレクトリのファイルを読ませてみる。
- **長大な CLAUDE.md にしてしまう**
  原因：何でも書き込んだ結果、重要な指示が埋もれる。対処：200 行未満を目安に削る。公式は `/doctor` が、コードから分かる内容の削減案を出してくれると説明している。
- **必ず守らせたいことを CLAUDE.md だけに書く**
  原因：CLAUDE.md は強制ではなく参考情報。対処：「必ず毎回実行」したい処理は hooks（中級で扱う）に任せる。
- **個人設定をチーム共有の CLAUDE.md に書いてコミットする**
  原因：置き場所の使い分けを知らない。対処：個人用は `CLAUDE.local.md`（.gitignore に追加）か `~/.claude/CLAUDE.md` に書く。
