## ゴール

- Claude Code に自然な言葉で依頼し、結果を確認する流れを理解する
- `@` でファイルを指定し、`!` でシェルコマンドを実行できる
- 中断・改行・巻き戻しなどの基本キー操作を使える

## 前提

- [インストールと初回起動](/learn/basic/install)が完了し、`claude` を起動できる
- 試せるプロジェクトのフォルダがある（Git 管理されているとなお良い）

## 解説

### 対話の基本

入力欄に依頼を書いて Enter で送信します。公式ドキュメントでも「同僚に頼むように、達成したいことを伝える」ことが勧められています。ファイルを自分で読み込ませる必要はなく、Claude が必要に応じてプロジェクト内のファイルを読みます。

曖昧な依頼より、具体的な依頼のほうが良い結果になります。

| 弱い依頼       | 強い依頼                                       |
| -------------- | ---------------------------------------------- |
| バグを直して   | ログイン失敗時に画面が真っ白になるバグを直して |
| テストを書いて | 計算関数のユニットテストを書いて               |

### ファイルを指定する `@`

`@` を入力するとファイルパスの補完が表示されます。Tab で候補を確定できます。特定のファイルを見てほしいときに使います。

### シェルモード `!`

行頭に `!` を付けると、コマンドを直接実行し、その出力をセッションに追加します。出力を踏まえて Claude に続きを頼めます。

### 変更の確認と承認

ファイルを変更する前に、Claude Code は内容を見せて確認を求めることがあります。許可するなら **Yes** を選びます。どの操作を確認なしで行うかは「権限モード」で決まります。`Shift+Tab` で切り替えられますが、詳細は[権限モード](/learn/basic/permission-modes)のレッスンで扱います。

### 覚えておきたいキー操作

| 操作              | キー                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| 応答の中断        | `Esc`                                                                     |
| 入力の消去 / 終了 | `Ctrl+C`（実行中は中断、何も実行していなければ入力を消去し、2回目で終了） |
| 終了              | `Ctrl+D` を2回、または `/exit`                                            |
| 改行              | `\` + `Enter`、または `Ctrl+J`                                            |
| 履歴              | `↑` / `Ctrl+R`（検索）                                                    |
| 巻き戻しメニュー  | 入力が空のとき `Esc` を2回                                                |
| 画面の乱れを直す  | `Ctrl+L`                                                                  |
| 詳細表示の切替    | `Ctrl+O`（ツールの実行内容を確認）                                        |

`Shift+Enter` での改行は、Windows Terminal や iTerm2 などでそのまま使えます。他の端末では `/terminal-setup` などの設定が必要な場合があります。

## ハンズオン

1. プロジェクトのフォルダで `claude` を起動します。

   ```bash
   claude
   ```

2. 構造を質問します。

   ```text
   explain the folder structure
   ```

   期待される結果: ファイル構成の説明が返ります。

3. `@` を入力し、候補から好きなファイルを選んで質問します。

   ```text
   @README.md を3行で要約して
   ```

   期待される結果: 指定したファイルを読んだ要約が返ります。

4. シェルモードで Git の状態を見ます（Git 管理のフォルダの場合）。

   ```text
   !git status
   ```

   期待される結果: `git status` の出力が表示され、セッションに追加されます。

5. 小さな変更を依頼します。

   ```text
   add a hello world function to the main file
   ```

   期待される結果: 変更内容が表示され、確認が出たら内容を読んでから **Yes** を選びます。

6. 結果を確認します。`Ctrl+O` で実行の詳細を見られます。思った結果でなければ、入力欄が空の状態で `Esc` を2回押して巻き戻しメニューを開きます。

7. `/exit` で終了します。

## よくある失敗

- **改行したいのに送信されてしまう**
  - 原因: Enter は送信のキー。
  - 対処: `\` を打ってから Enter、または `Ctrl+J` を使う。
- **依頼が曖昧で、期待と違う変更をされる**
  - 原因: 対象・条件・期待する結果が伝わっていない。
  - 対処: 対象ファイル（`@`）、症状、期待する結果を具体的に書く。
- **変更内容を読まずに Yes を押し続ける**
  - 原因: 確認ダイアログに慣れてしまう。
  - 対処: 差分を読んでから承認する。意図しない変更は巻き戻しメニューや Git で戻せるよう、作業前にコミットしておく。
- **`Ctrl+C` で意図せず終了した**
  - 原因: 何も実行していないときに2回押すと終了する。
  - 対処: 中断だけなら `Esc` を使う。
- **`!` を行頭以外に書いてしまう**
  - 原因: `!` は行頭でのみシェルモードになる。
  - 対処: 行の先頭に書く。
