## ゴール

- Plan Modeが何をして、何をしないかを説明できる
- 入り方、計画の承認方法、計画の修正方法を実行できる
- Plan Modeを使うべき場面と、不要な場面を見分けられる

## 前提

- 権限モードの概要を理解していること(レッスン4)
- 小さなプロジェクトか練習用フォルダがあること

用語の説明です。**Plan Mode** は、Claudeにコードを読ませて調べさせ、変更案(計画)を作らせるが、ソースの編集はさせない権限モードです。設定値は `plan` です。

## 解説

### なぜ計画が必要か

いきなり実装させると、Claudeが方向を取り違えたとき、直した変更を全部やり直すことになります。先に計画だけを出させて人間が確認すれば、手戻りを防げます。公式のコスト管理の解説でも、複雑な作業の前にPlan Modeを使うことが推奨されています。

### Plan Modeの入り方

| 方法                    | 操作                                                  |
| :---------------------- | :---------------------------------------------------- |
| 実行中にモード切り替え  | `Shift+Tab` を押して `plan mode on` を表示させる      |
| 1回の依頼だけ計画にする | 先頭に `/plan` を付ける。例: `/plan 認証のバグを直す` |
| 起動時から              | `claude --permission-mode plan`                       |

`Shift+Tab` をもう一度押すと、計画を承認せずにPlan Modeを抜けます。

### 計画の承認

計画ができると、Claudeは次のような選択肢を出します(選択肢の文言は環境により変わります)。

- **Yes, and use auto mode**: 承認して auto モードで実装を始める。auto が使えない環境では `Yes, auto-accept edits` と表示される
- **Yes, manually approve edits**: 承認し、各編集を1つずつ確認しながら進める
- **No, keep planning**: 計画を続ける。直してほしい点を伝える

承認するとPlan Modeは終わり、選んだモードに切り替わって編集が始まります。もう一度計画したいときは `Shift+Tab` か `/plan` で戻ります。

`Ctrl+G` を押すと、提案された計画を既定のテキストエディタで開き、直接修正してから進められます。

### 向いている場面

- 複数ファイルにまたがる変更
- 不慣れなコードベースの調査
- 方針が複数ありうる設計の相談

誤字修正のような小さな変更では、計画を挟まず直接依頼するほうが速いです。

### 計画のあいだの安全面

Plan Modeでも、Claudeは調査のためにシェルコマンドを実行することがあります。どのコマンドが確認なしで動くかは環境(auto モードが使えるかなど)で変わります。ソースの編集は、計画を承認するまでブロックされます。なお、`bypassPermissions` を有効にして起動した対話ターミナルでは、この編集ブロックは強制されません。このモードの危険性はレッスン4を参照してください。

## ハンズオン

1. 練習用のプロジェクトフォルダでClaude Codeを起動します。
2. 次のように、計画だけを依頼します。

   ```text
   /plan このプロジェクトに README.md を追加したい。含めるべき項目と手順を提案して
   ```

   期待される結果: ステータスバーに `plan mode on` が出ます。Claudeはファイルを読んで調べ、計画を提示します。ファイルはまだ作られません。

3. 計画が出たら、`Ctrl+G` で計画をエディタで開き、項目を1つ削除するなど編集して閉じます(エディタが開かない環境ではスキップして構いません)。
4. 選択肢から `No, keep planning` を選び、次のように伝えます。

   ```text
   セットアップ手順の節を最初に置いて
   ```

   期待される結果: 計画が更新されて再提示されます。

5. 計画に納得したら `Yes, manually approve edits` を選びます。

   期待される結果: Plan Modeが終了し、`README.md` の作成について確認が出ます。内容を確認して承認します。

## よくある失敗

- **計画の中身を読まずに承認する**
  - 原因: 承認すれば実装が始まると知らずに、流れで選ぶ
  - 対処: 変更対象のファイルと手順を必ず読む。不安なら `Yes, manually approve edits` を選び、1編集ずつ確認する
- **Plan Modeに入ったつもりで依頼して、そのまま実装された**
  - 原因: モードを切り替えたつもりで、ステータスバーを確認していない
  - 対処: `plan mode on` の表示を確認してから依頼する。または確実に `/plan` を先頭に付ける
- **小さな修正でも毎回Plan Modeを使って遅くなる**
  - 原因: 使い分けの基準がない
  - 対処: 影響範囲が広い、または方針が定まらないときだけ使う
- **計画が漠然としている**
  - 原因: 依頼が曖昧で、調査の観点が絞れていない
  - 対処: 目的、制約、触ってよい範囲を依頼に書く。計画の段階で `No, keep planning` で具体化させる
- **`bypassPermissions` を有効にしたまま、計画中の安全を信じる**
  - 原因: 対話ターミナルではPlan Modeの編集ブロックが強制されない
  - 対処: 計画を重視する作業では、このモードで起動しない
