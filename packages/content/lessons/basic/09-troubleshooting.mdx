## ゴール

- 症状から、どの診断コマンドを使うか選べる
- `/doctor`、`/context`、`/status` の役割の違いを説明できる
- カスタマイズが原因かどうかを `--safe-mode` で切り分けられる

## 前提

- Claude Code を起動でき、`/` から始まるスラッシュコマンド（Claude Code の操作コマンド）を使える
- 前のレッスンで CLAUDE.md と `/context` を触った

## 解説

困ったときは、推測で設定をいじる前に、Claude Code が実際に何を読み込んでいるかを確認します。公式の「Debug your configuration」と「Troubleshooting」のページに沿って整理します。

### 診断コマンドの早見表

| 確認したいこと       | コマンド                        | 分かること                                                                                                             |
| -------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 全体の健康診断       | `/doctor`                       | インストール、不正な設定ファイル、未使用の拡張機能、コンテキスト使用量などを確認し、修正案を出す。適用前に確認を求める |
| 起動しない場合       | `claude doctor`（シェルで実行） | セッションを開始せず、インストールと設定の診断を読み取り専用で表示                                                     |
| 何が読み込まれたか   | `/context`                      | メモリファイル、スキル、MCPツール、会話などの内訳                                                                      |
| メモリファイルの場所 | `/memory`                       | CLAUDE.md などの場所と、auto memory の切り替え                                                                         |
| 有効な設定の出どころ | `/status`                       | どの設定ソースが有効か（管理設定を含む）                                                                               |
| 権限ルール           | `/permissions`                  | 現在有効な許可・拒否ルール                                                                                             |
| MCPサーバー          | `/mcp`                          | 接続状態                                                                                                               |
| hooks                | `/hooks`                        | 登録済みの hook                                                                                                        |

### 症状から選ぶ

- インストール・ログイン系（`command not found`、`'claude' is not recognized` など）：公式の「Troubleshoot installation and login」を参照します。まず `claude --version` でバージョンが表示されるか確認します。表示されなければ PATH（コマンドを探すフォルダの一覧）の問題で、インストール直後は新しいターミナルを開き直します。ログインのやり直しは `/login` です。
- Claude が指示を守らない：`/context` で CLAUDE.md が読み込まれているか確認します。読み込まれていれば、書き方（曖昧・矛盾・長すぎ）が原因です。
- 動作が重い・応答が遅い：`/compact` で会話を要約します。作業の区切りで Claude Code を再起動し、`claude --continue` で会話を再開できます。
- 固まった：`Ctrl+C` で中断します。ダメなら端末を閉じ、同じディレクトリで `claude --resume` を実行すれば会話を戻せます。
- 設定が効かない：設定は管理・ユーザー・プロジェクト・ローカルの各スコープで統合され、環境変数やフラグでも上書きされます。`/status` で有効なソースを確認します。

### カスタマイズが原因か切り分ける

`claude --safe-mode` で起動すると、CLAUDE.md、スキル、プラグイン、hooks、MCPサーバーなどが無効になります。認証、モデル選択、組み込みツール、権限は通常どおり動きます。問題が消えれば、原因はそのどれかです。

### それでも解決しない場合

公式は、`/feedback` で Anthropic へ直接報告する方法と、GitHub リポジトリの既知の問題の確認を案内しています。Claude 自身に機能について尋ねることもできます。

## ハンズオン

1. Claude Code を起動して、総合チェックを実行します。

   ```text
   /doctor
   ```

   期待される結果：インストールや設定の診断結果が表示されます。問題があれば修正案が提示され、適用前に確認を求められます。内容を読んでから許可してください。

2. 読み込み内容を確認します。

   ```text
   /context
   ```

   期待される結果：カテゴリ別の内訳が出ます。前のレッスンで作った CLAUDE.md が Memory files にあるか確認します。

3. 設定の出どころを確認します。

   ```text
   /status
   ```

   期待される結果：有効な設定ソースが表示されます。

4. Claude Code を `/exit` で終了し、シェルで次を実行します。

   ```bash
   claude doctor
   claude --version
   ```

   期待される結果：診断結果と、`2.1.211 (Claude Code)` のようなバージョン番号が表示されます（番号は環境により異なります）。

5. 切り分けの練習として、安全モードで起動します。

   ```bash
   claude --safe-mode
   ```

   期待される結果：CLAUDE.md などのカスタマイズなしで起動します。ここで `/context` を実行し、Memory files に CLAUDE.md が出ないことを確認して、通常起動と比べてください。

## よくある失敗

- **診断せず設定ファイルを手で書き換え続ける**
  原因：何が読み込まれているか分からないまま試行錯誤している。対処：`/context` と `/status` で現状を確認してから直す。
- **`/doctor` の修正案をよく読まずに許可する**
  原因：自動で直るという思い込み。対処：提案内容を確認してから適用する。適用前に確認を求められる仕様なので、読んで判断する。
- **インストール直後に `claude` が見つからない**
  原因：インストールしたターミナルは古い PATH を保持している。対処：新しいターミナルを開いて `claude --version` を試す。それでもダメなら公式のインストール・ログインのトラブルシュートを参照する。
- **起動しないのにセッション内のコマンドを探す**
  原因：`/doctor` はセッション内でしか使えない。対処：シェルから `claude doctor` を実行する。
- **サブディレクトリの CLAUDE.md が `/context` に出ないので異常だと思う**
  原因：サブディレクトリの CLAUDE.md は起動時ではなく、必要になった時に読み込まれる。対処：そのディレクトリのファイルを Claude に読ませて確認する。
