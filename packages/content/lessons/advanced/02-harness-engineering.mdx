## ゴール

- 「Claude が自分で正しさを確かめられる環境（ハーネス）」とは何かを説明できる
- hooks の終了コードの意味を理解し、整形・停止時検証・危険コマンドのブロックを設計できる
- 検証を 1 コマンドにまとめ、ローカルと CI で同じ判定を使える

## 前提

- 中級で hooks の基本（`settings.json` への書き方）を学んでいる
- プロジェクトにテスト・型チェック・lint のコマンドがある（なければ、まずテストを 1 つ用意する）
- Node.js が使える（ハンズオンのスクリプトは Node で書く）

## 解説

### なぜハーネスが必要か

ハーネス（harness）は、もともと「テストを走らせるための仕掛け」を指す言葉です。ここでは、Claude が書いた変更を、人間の確認を待たずに機械的に検証し、失敗したら自分で直せる仕組み全体を指します。

CLAUDE.md の指示は参考情報であり、強制ではありません。「テストを通してから終わる」と書いても、守られる保証はありません。守らせたいことは、終了コードで判定できる形にして、hooks などの強制力のある仕組みに任せます。

### 3 つの層で作る

| 層           | 役割                                | 例                                                                                   |
| ------------ | ----------------------------------- | ------------------------------------------------------------------------------------ |
| 検証コマンド | 正しさの判定そのもの                | `pnpm verify`（format・lint・typecheck・test・build を順に実行し、失敗で非ゼロ終了） |
| hooks        | Claude の動きの途中に判定を差し込む | 編集後の整形、停止前のテスト、危険コマンドのブロック                                 |
| CI           | 人間・Claude を問わず最後の砦       | プルリクエストで同じ `pnpm verify` を実行                                            |

### hooks の終了コード（公式の仕様）

| 終了コード       | 意味                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------- |
| 0                | 成功。「判断なし」で、通常の権限判定に進む                                                |
| 2                | ブロッキングエラー。ブロックできるイベントでは、その動作を止める。stderr が Claude に渡る |
| その他（1 など） | 非ブロッキングエラー。動作はそのまま進み、記録に注意が出る                                |

特に重要なのは、`exit 1` ではブロックされない点です。ポリシーを強制したいときは必ず `exit 2` を使います。

### イベントごとの使い分け

- PreToolUse（ツール実行前）: 実行を止められる。危険コマンドのブロックに向く。JSON 出力の `permissionDecision`（`allow` / `deny` / `ask` / `defer`）でも制御できる
- PostToolUse（ツール成功後）: すでに実行済みなので止められない。整形や、直せない問題を Claude に伝えるのに向く
- Stop（Claude が応答を終えるとき）: exit 2 か `"decision": "block"` で、停止を止めて続行させられる。入力の `stop_hook_active` が true なら、すでに続行中という意味なので、ブロックを繰り返さないようにする。公式によれば、連続する続行は 8 回までに制限される

### このリポジトリの実例

`.claude/settings.json` に、次の 3 つの hook が登録されています。

- `PreToolUse`（`Bash`）: `guard-bash.mjs` が `rm -rf`、force push、`.env` の `git add` などを検出し、`exit 2` で拒否する
- `PostToolUse`（`Edit|Write|MultiEdit`）: `format.mjs` が編集したファイルに prettier と `eslint --fix` を適用し、直せない lint エラーがあるときだけ `exit 2`
- `Stop`: `stop-verify.mjs` が `pnpm typecheck` と `pnpm test` を実行し、失敗なら `exit 2`。`stop_hook_active` なら何もしない

Stop hook では typecheck と test だけを走らせ、build や format は含めていません。毎回の停止で待たされる時間を抑えるためです。完全な検証は `pnpm verify`（`scripts/verify.mjs`）に任せ、CI でも同じコマンドを実行します。

### 完了条件を機械的にする

「きれいに直して」ではなく、「`pnpm verify` が終了コード 0 で終わる」を完了条件にします。条件が曖昧だと、Claude は自分で成否を判断できず、ループが回りません。

## ハンズオン

練習用の Node プロジェクト（`package.json` があり、`npm test` が動くもの）で、Stop 時にテストを走らせるハーネスを作ります。

1. フォルダを作り、検証スクリプト `.claude/hooks/stop-verify.mjs` を作ります。

   ```javascript
   // Stop hook: 失敗していれば exit 2 で Claude に続行させる
   import { spawnSync } from 'node:child_process';

   let data = '';
   process.stdin.setEncoding('utf8');
   for await (const chunk of process.stdin) data += chunk;

   const input = JSON.parse(data || '{}');
   if (input.stop_hook_active) process.exit(0); // 無限ループ防止

   const r = spawnSync('npm', ['test'], { encoding: 'utf8', shell: true });
   if (r.status !== 0) {
     const tail = `${r.stdout}${r.stderr}`.split('\n').slice(-40).join('\n');
     console.error(`npm test が失敗しました。修正してください:\n${tail}`);
     process.exit(2);
   }
   ```

2. `.claude/settings.json` に登録します。

   ```json
   {
     "hooks": {
       "Stop": [
         {
           "hooks": [
             {
               "type": "command",
               "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/stop-verify.mjs\"",
               "timeout": 300
             }
           ]
         }
       ]
     }
   }
   ```

3. 危険コマンドのブロックも追加します。`.claude/hooks/guard.mjs` を作ります。

   ```javascript
   let data = '';
   process.stdin.setEncoding('utf8');
   for await (const chunk of process.stdin) data += chunk;

   const command = JSON.parse(data || '{}')?.tool_input?.command ?? '';
   if (/\bgit\s+reset\s+--hard\b/.test(command)) {
     console.error('git reset --hard は禁止です');
     process.exit(2);
   }
   ```

   `settings.json` の `hooks` に、`PreToolUse` を `matcher` が `Bash` で追加します。

   ```json
   "PreToolUse": [
     {
       "matcher": "Bash",
       "hooks": [
         { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard.mjs\"" }
       ]
     }
   ]
   ```

4. Claude Code を起動し直し、わざとテストを壊させます。

   ```text
   テストの期待値を間違った値に書き換えて、そのまま終わって
   ```

   期待される結果：Claude が応答を終えようとすると Stop hook が `npm test` を実行して失敗し、エラー内容が Claude に返ります。Claude は続行してテストを直します。

5. 危険コマンドを試します。

   ```text
   git reset --hard を実行して
   ```

   期待される結果：実行前にブロックされ、`git reset --hard は禁止です` が Claude に伝わります。

## よくある失敗

- **hook が失敗しているのに止まらない**
  原因：`exit 1` で終了している。1 は非ブロッキングエラーで、動作は続行される。対処：止めたいときは `exit 2` を使い、理由を stderr に出す。
- **Stop hook が延々と Claude を動かし続ける**
  原因：`stop_hook_active` を見ておらず、直せない失敗でブロックを繰り返す。対処：`stop_hook_active` が true なら `exit 0`。公式の上限は連続 8 回だが、それに頼らない。
- **PostToolUse でブロックしようとして効かない**
  原因：PostToolUse はツール実行後なので止められない。対処：事前に止めたい処理は PreToolUse に置く。
- **Windows で hook が動かない・パスが合わない**
  原因：`tool_input.file_path` の区切りがバックスラッシュになる。対処：パスを正規化してから判定する。
- **ローカルでは通るのに CI で落ちる**
  原因：ローカルと CI で検証内容が違う。対処：`pnpm verify` のように 1 コマンドにして、CI でも同じものを実行する。
