## ゴール

- トークン消費が増える仕組み（会話全体を毎回送る、キャッシュ、サブエージェント）を説明できる
- `/usage`、`/context`、`/compact`、`/clear` を、コスト・品質の観点で使い分けられる
- サブエージェント、Plan Mode、モデル選択、CLAUDE.mdの整理で、消費と手戻りを減らせる

## 前提

- 基礎レッスンのコンテキスト管理（`/learn/basic/context-management`）とPlan Mode（`/learn/basic/plan-mode`）を終えていること
- コマンドの基本的な使い方はそちらで扱いました。ここでは「なぜ・いつ使うか」というコスト設計に絞ります

**トークン** は、モデルが処理する量の単位です。Claude Codeは、トークンの消費量をもとに課金や利用上限が決まります。料金や上限の数値は、プラン・契約・時期で変わるため、このレッスンでは書きません。確認方法は後述します。

## 解説

### コストの正体はコンテキストの大きさ

公式によると、コストはおおむねコンテキストの大きさに比例します。Claude Codeは、リクエストのたびに会話全体を送ります。ツールを使うたびに追加のリクエストが飛び、そこにも履歴が付くため、一日中開いたままのセッションでは、一行の質問でも履歴全体分の利用量がかかります。

さらに、**プロンプトキャッシュ**（繰り返し送る内容を安く処理する仕組み）の有効期間を過ぎてから再開すると、最初のメッセージで全体を再処理します。有効期間はプランや認証方法で異なります。公式のコストのページで確認してください。

つまり、**会話を小さく保つこと** が、コストにも品質にも効きます。

### 確認するコマンド

| コマンド | 見えるもの |
| :-- | :-- |
| `/usage`（別名 `/cost`） | セッションのトークン使用量と金額の見積り。Pro/Max/Team/Enterpriseでは、プランの利用上限の内訳も出る |
| `/context` | 何がコンテキストを占めているか。MCPやメモリの肥大の発見に使う |
| ステータスライン | コンテキスト使用量を常時表示できる |

`/usage` の金額は、トークン数から **ローカルで計算した見積り** です。正式な請求は、API利用ならClaude Consoleの利用状況ページで確認します。管理者が管理設定に `modelPricing` を設定している場合は、契約単価で計算されます。

### 整理するコマンドの使い分け

| 状況 | 操作 | 理由 |
| :-- | :-- | :-- |
| 無関係な作業へ移る | `/clear` | 追加コストなしで空にできる。`/rename` で名前を付ければ `/resume` で戻れる |
| 同じ作業を続けたいが長い | `/compact 残したい内容` | 要約で圧縮する。ただし要約自体が大きなリクエストになる |
| 方向を誤った | `Esc`、`/rewind` | 間違いを積んだ会話を要約するより、戻るほうがきれい |

### 読み込みを減らす設計

- **サブエージェントで分離する。** テスト、ドキュメント取得、ログ処理のように出力が多い作業は、サブエージェントに任せます。冗長な出力は向こうのコンテキストに残り、メインには要約だけ戻ります。ただしサブエージェントの利用分も数えられます。単純な作業には、`model: haiku` のように安いモデルを指定できます
- **Plan Modeで手戻りを減らす。** 実装前に方針を承認すれば、最初の方向が違ったときの高コストなやり直しを避けられます
- **モデルを使い分ける。** 公式は、多くのコーディング作業はSonnetで十分で、複雑な設計判断や多段階の推論にOpusを使うことを勧めています。`/model` で切り替えられます。Opusに切り替えると、モデルを引き継ぐサブエージェントにも適用されます
- **思考量を調整する。** 拡張思考（extended thinking）のトークンは出力として課金されます。簡単な作業では `/effort` で下げられます。ただし、モデルによっては思考をオフにできません
- **CLAUDE.mdを短く保つ。** 毎セッションの開始時に読み込まれます。公式は1ファイル200行未満を目安にし、特定作業だけに必要な手順をスキルに移すよう勧めています。スキルは必要なときだけ読み込まれます。インポートは整理に役立ちますが、読み込み量は減りません
- **MCPと前処理を見直す。** MCPツールの定義は既定で遅延読み込みですが、使っていないサーバーは `/mcp` で無効にできます。`gh` のようなCLIツールは、MCPより省コンテキストです。フックでログをフィルタし、必要な行だけ渡す方法もあります

### このリポジトリの例

このリポジトリの `CLAUDE.md` は、構成・コマンド・原則・参照先だけに絞り、パス別の規約は `.claude/rules/`、手順は `.claude/skills/` に分けています（理由は `docs/claude-layout.md`）。「いつ読まれるか」で置き場所を分ける設計です。

## ハンズオン

練習用のプロジェクトで、消費を観察しながら整理します。

1. Claude Codeを起動し、まず基準値を見ます。

   ```text
   /context
   ```

   期待される結果: 使用状況のグリッドが表示されます。何もしていない段階でも、システムプロンプトやCLAUDE.md、MCPなどがすでにコンテキストを占めていることがわかります。

2. 出力の多い作業を、サブエージェントに任せます（テストが無い場合は、別の出力が多いコマンドで構いません）。

   ```text
   サブエージェントを使って、テストスイートを実行し、失敗したテストとそのエラーメッセージだけを報告して
   ```

   期待される結果: 実行ログの全文ではなく、要約が会話に返ります。もう一度 `/context` を実行し、同じ作業をメインの会話で直接実行した場合と比べて、増加が小さいかを見比べます（増加量はプロジェクトで変わります）。

3. 使用量を確認します。

   ```text
   /usage
   ```

   期待される結果: セッションのトークン使用量と、金額の見積りが出ます。サブスクリプションの場合は、プランの利用状況も表示されます。金額は見積りであり、請求の正式な値ではない点に注意してください。

4. 要約の焦点を指定して圧縮し、その後で新しい会話に切り替えます。

   ```text
   /compact 変更したファイルと、未解決の課題だけ残して
   /clear cost-practice
   ```

   期待される結果: 要約に置き換わったあと、名前付きで会話が保存され、空の会話が始まります。`/resume` で戻れます。

5. CLAUDE.mdの行数を測ります（PowerShell）。

   ```powershell
   (Get-Content CLAUDE.md).Count
   ```

   macOS/Linuxなら `wc -l CLAUDE.md` です。

   期待される結果: 行数が表示されます。200行を超えていたら、特定の作業にしか要らない部分を、スキルかパス指定のルールに移す候補として洗い出します。

## よくある失敗

- **一日中、同じ会話を使い続ける**
  - 原因: 履歴が積み上がり、毎回のリクエストが大きくなる。キャッシュ期限切れ後の再開では全体を再処理する
  - 対処: 作業の区切りで `/clear`。`/rename` で名前を付ければ `/resume` で戻れる
- **容量が不安で `/compact` を何度も実行する**
  - 原因: `/compact` は会話を読んで要約するため、それ自体が大きなリクエストになる
  - 対処: 無関係な作業に移るなら `/clear` のほうが軽い。続けるなら、残す内容を指示して1回で済ませる
- **何でもOpus、何でも深い思考で動かす**
  - 原因: 既定のモデルや思考量をそのまま使っている
  - 対処: 通常はSonnetで進め、難しい設計判断だけOpusにする。簡単な作業は `/effort` を下げる
- **CLAUDE.mdに全部書いて肥大化する**
  - 原因: 手順書やルールを何でも入れ、毎回読み込まれる
  - 対処: 200行未満を目安に、手順はスキル、パス別の規約は `.claude/rules/` に移す
- **`/usage` の金額を請求額だと思う**
  - 原因: 見積りだと知らない。サブスクリプションでは金額自体が請求の目安にならない
  - 対処: 請求はConsoleの利用状況ページで確認する。チームの上限や分析は、管理者向けの機能（公式の costs ページ）を使う
