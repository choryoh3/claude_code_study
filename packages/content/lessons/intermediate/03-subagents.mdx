## ゴール

- サブエージェントとは何か、スキルとの違いを説明できる
- `.claude/agents/` にエージェントを定義し、`tools` で権限を絞れる
- Claude に任せる方法と、名前を指定して呼ぶ方法を使い分けられる

## 前提

- [skills](/learn/intermediate/skills) のレッスンを終えている
- [settings.json](/learn/intermediate/settings) の `permissions` の考え方を知っている

用語の説明です。**サブエージェント** は、特定の役割（例: コードレビュー）を持った別のAIアシスタントです。メインの会話とは別のコンテキストで動き、作業が終わると結果の要約だけを返します。

## 解説

### なぜ分けるのか

大きな調査では、ファイルの読み込みや検索結果などの長い出力がメインの会話を埋めてしまいます。サブエージェントに任せると、その途中経過はサブエージェント側に閉じ、メインには要約だけが入ります。また、役割ごとに使える `tools` やモデルを変えられます。

サブエージェントは、次のものを含む新しいコンテキストで始まります。

- 自分のシステムプロンプト（ファイルの本文）と、親から受け取った依頼文
- CLAUDE.md と git status
- `skills` で指定したスキルの内容

あなたとメインの会話の履歴は見えません。だから、依頼文には必要な情報をすべて書きます。

### 定義するファイル

`.claude/agents/` に Markdown を置きます。本文がシステムプロンプトになり、`name` と `description` だけが必須です。

```markdown
---
name: doc-reviewer
description: ドキュメントの誤字・曖昧な表現を指摘する。文章をレビューしてほしいときに使う。
tools: Read, Grep, Glob
model: sonnet
---

あなたは日本語の校正者です。指定されたファイルを読み、誤字と曖昧な表現を指摘してください。
ファイルは編集せず、指摘は「場所・問題・修正案」の3点で書いてください。
```

### 置き場所と優先順位

| 優先度 | 場所 | 範囲 |
| :-- | :-- | :-- |
| 1（高） | 組織の管理設定 | 組織全体 |
| 2 | `--agents` フラグ | そのセッションだけ（ディスクに保存されない） |
| 3 | `.claude/agents/` | このプロジェクト（コミットして共有） |
| 4 | `~/.claude/agents/` | 自分の全プロジェクト |
| 5（低） | プラグインの `agents/` | プラグインを有効にした範囲 |

同名なら優先度の高いほうが使われます。サブフォルダに分けても構いません。識別に使われるのは `name` だけで、パスは関係ありません。

### 主な frontmatter

| 項目 | 意味 |
| :-- | :-- |
| `name` / `description` | 必須。`description` は、Claude が任せるかどうかを判断する根拠 |
| `tools` | 使えるツールの許可リスト。**省略すると、使えるツールをすべて引き継ぐ** |
| `disallowedTools` | 拒否リスト。`tools` より先に適用される |
| `model` | `sonnet`、`opus`、`haiku`、完全なモデルID、`inherit` など |
| `permissionMode` | このエージェントの権限モード。親が `bypassPermissions` などのときは親が優先される |
| `skills` | 起動時に内容を注入するスキル |
| `memory` | 永続メモリの範囲（`user`、`project`、`local`） |
| `maxTurns` | 動作できる最大ターン数 |

項目名は camelCase で完全一致が必要です。未知の項目はエラーにならず無視されます。

### 呼び出し方

```text
doc-reviewer サブエージェントを使って README.md をレビューして
```

```text
@"doc-reviewer (agent)" README.md を見て
```

```bash
claude --agent doc-reviewer
```

1つ目は自然な依頼で、Claude が名前を見て任せます。2つ目は `@` で名前を明示する方法です。3つ目の `--agent` は、セッション全体をそのエージェントとして動かします。何も指定しなくても、Claude は `description` を見て自動で任せることがあります。

### 組み込みのサブエージェント

自分で作らなくても `Explore`（読み取り専用の高速な探索）、`Plan`（プランモードでの調査）、`general-purpose`（探索と変更の両方ができる汎用）があります。不要なものは `permissions.deny` に `Agent(Explore)` のように書いて止められます。

### `/agents` コマンドの注意

`/agents` の動作はバージョンで違います。公式によれば v2.1.197 以前は管理用の画面が開きますが、それ以降は、Claude に作成を頼むか `.claude/agents/` を直接編集するよう案内が表示されます。この教材ではファイルを直接編集する方法を使います。

## ハンズオン

1. 練習用フォルダにエージェントのファイルを作ります（先に作ってから起動すると、再起動が要りません）。

   ```bash
   mkdir agents-practice
   cd agents-practice
   mkdir -p .claude/agents
   printf "# 練習\nこれは、てすとようの文書です。たぶん動きます。\n" > README.md
   ```

2. `.claude/agents/doc-reviewer.md` を、上の「定義するファイル」の例と同じ内容で保存します。
3. `claude` を起動し、名前を指定して依頼します。

   ```text
   doc-reviewer サブエージェントを使って README.md をレビューして
   ```

   期待される結果: サブエージェントが動いた表示のあと、「たぶん動きます」のような曖昧な表現などについて、場所・問題・修正案の形で要約が返ります。
4. `@` 指定でも試します。`@` に続けて `doc` と入力すると候補が出ます。

   ```text
   @"doc-reviewer (agent)" README.md をもう一度見て
   ```

5. `tools` から `Grep, Glob` を消して `Read` だけにし、保存します。数秒待ってから再度依頼します。
   期待される結果: 再起動なしで、新しい定義（使えるツールが少ない状態）で動きます。
6. 書き込みを試します。

   ```text
   doc-reviewer サブエージェントで README.md の誤字を直して
   ```

   期待される結果: `tools` に `Edit` と `Write` がないため、サブエージェント自身はファイルを編集できません。修正案の提示までで止まるか、編集をメインの会話側で行う提案になります（応答の細部は実行ごとに変わります）。

## よくある失敗

- **読み取り専用のつもりが、書き込みもされる**
  - 原因: `tools` を省略している、または本文に「編集しない」と書いただけ。`tools` を省略すると、使えるツールをすべて引き継ぎます。`Bash` を許可すると、コマンド経由で変更できます
  - 対処: `tools` で許可リストを書く。変更を禁じたいツールは `disallowedTools: Write, Edit` で外す
- **任せたい場面で使われない**
  - 原因: `description` が抽象的で、いつ使うのか分からない
  - 対処: 「コミット前に差分をレビューするときに使う」のように場面を書く。積極的に使わせたいなら、公式が例示するように「use proactively」にあたる表現を加える
- **サブエージェントが文脈を知らず的外れな結果を返す**
  - 原因: 会話履歴が見えない
  - 対処: 依頼文に、対象ファイル・目的・制約を書く。必要な背景は CLAUDE.md や `skills` で渡す
- **新しい定義が反映されない**
  - 原因: 新規の `agents` ディレクトリの最初のファイル、`--add-dir` で追加したディレクトリ内の編集などは、再起動が必要
  - 対処: 一度終了して `claude` を起動し直す
- **定義を増やしすぎる**
  - 原因: 説明文が長いエージェントを大量に作った
  - 対処: `description` は短くする。公式は、カスタムエージェントの説明が合計15,000トークンを超えると起動時に警告が出ると説明している
